JoinSheets —  создавался как часть более масштабного проекта по управлению данными.
Исходнй задачей приложения было дать пользователям BI-платформы удобный пользовательский интерфейс,
позволяющий увидеть один и тот же общий набор данных под разными углами.
Со временем JoinSheets был выделен в отдельный продукт,
реализующий функционал конструктор а табличных отображений поверх плоских таблиц.

JoinSheets обладает следующей функциональностью для работы с данными:

- импорт и экспорт табличных данных в наиболее распространенных форматах (Excel, CSV, JSON),
- объединение таблиц на основе оперций с множествами (left/right/inner/full join),
- формирование среза данных (выбор полей, установка ограничений по условиям),
- построение пользовательских отображений (конструктор таблиц),
- нормализации данных (приведение данных к единому типу и формату),
- разрешение коллизий, возникающих при работе с данными,
- поддержка работы с формулами для формирования расчетных полей,
- поддержка основных табличных операций (группировка, сортировка, поиск, фильтрация),
- возможность сохранения и переиспользования настроек пользовательских отображений.

## Построение пользовательских отображений

JoinSheets позволяет каждому пользователю настроить своё представление —
установить собственный набор полей и порядок их отображения, свои связки,
свои условия отбора и правила формирования показателей — на основе общего
набора данных.

Главное требование к функциональности: гибкая, **декларативная** настройка отображения
поверх общего датасета — с возможностью сохранить её, загрузить заново, передать
другому пользователю или переключаться между несколькими такими настройками,
переиспользовать для построения нового пользовательского отображения.
Настройка пользовательского отображения (пресет) описывает желаемый результат,
а не последовательность действий

Декларативная — поскольку пользователдь ничего не изменяет в исходных данных, он
только описывает, каким должно быть отображение результата: какие поля, как разрешены
коллизии между источниками, какие связки и условия. Пользовательский срез собирается
заново при каждом построении, данные из источников при этом остаются без изменений.


По сути JoinSheets — это ручная, декларативная реализация идеи, которая в
экосистеме `ds` называлась **Level 2**: разрешение коллизий между источниками по
весам доверия и сведение разноимённых полей разных источников в одну сущность.
Не автоматическая и не один-в-один по исходному замыслу — но именно эту задачу
решает приложение, и именно для неё оно строилось.


## Объединение таблиц

JoinSheets создавался для пользователей, не обладающих глубокими навыками SQL
и аналитики данных.

Визуальные средства работы аналог SQL-запросов.

 

JoinSheets нацелен на решение задач, решение которых в Excel

Часть задач в самом Excel либо недоступна рядовому пользователю,
либо требует наличия дополнительных надстроек (например, Power Query),

**Объединение нескольких плоских таблиц по ключу** — простая связка
без формул вида ВПР на каждую строку.

Остальное — поиск, сортировка, группировка, фильтрация, формульные поля — уже
привычный минимум табличного редактора, который тоже есть, но это не то, ради
чего приложение строилось.

  сам JoinSheets.
- **Типы данных, которые реально встречаются в таблице.** Текст, даты, числа,
  булевы и пустые значения, последовательно парсятся и типизируются.
- **Разрешение коллизий на основе приоритета.** Когда одно и то же поле
  доступно больше чем из одного источника, в результат попадает то, которому
  стоит доверять больше — по явно заданному весу, не по совпадению или дате
  (подробнее о том, почему именно так, — в свёрнутом блоке ниже).
