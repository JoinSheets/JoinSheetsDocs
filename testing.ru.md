Этот раздел описывает принятую на проекте систему тестирования: основные
виды тестов и то, какой из них за что отвечает. Перед тем как открывать
pull request, убедитесь, что сделанные изменения ничего не сломали.

У JoinSheets нет автоматизированного CI — полный набор тестов запускается
вручную перед каждым релизом. Самостоятельный прогон тестов перед открытием
pull request — минимальная страховка от внезапных падений при слиянии и от
неявных конфликтов.

{{< mermaid >}}
flowchart TB
  U[Юнит-тесты — чистые функции] --> S[Smoke-тест — настоящий бутстрап в DOM-заглушке]
  S --> B[Ручная проверка в браузере — DOM/UI, которого не видит заглушка]
{{< /mermaid >}}

Три слоя не заменяют друг друга, а покрывают разное: юнит-тесты быстро и
точно проверяют логику без браузера, smoke-тест проверяет, что модули вообще
правильно связались между собой, а браузер — то, что не умеет сымитировать
ни один из первых двух.

## Юнит-тесты

Для юнит-тестов используется обычный
[`node:test`](https://nodejs.org/api/test.html) (встроенный тест-раннер
Node, без зависимости от тестового фреймворка), в `tests/`. Скрипт для
запуска полного набора:

```bash
./run_tests.sh
```

(тонкая обёртка над `node --test tests/*.test.js` — явный список файлов, а
не рекурсивный поиск, чтобы тесты опционального submodule `import/` не
попадали в этот прогон, см. [Технические решения](../technical-decisions/)).

| Файл | Покрывает |
|---|---|
| `dataset.test.js` | Объединение источников, условия отбора, расширенный фильтр, сортировку. |
| `entities.test.js` | Парсинг чисел/дат/булевых значений, типизацию, разрешение коллизий — самая рискованная логика в приложении: граничные случаи (Excel-даты в виде serial-номера, неоднозначные разделители) проще всего сломать правкой «на глаз». |
| `export.test.js` | Экспорт в CSV/Excel и построение имени файла экспорта. |
| `formula.test.js` | Токенизатор/парсер/вычислитель формульных полей. |
| `preset.test.js` | Нормализацию пресета и редьюсер стора — самый большой файл, поскольку большинство пользовательских действий — это кейсы редьюсера. |

Это тесты на чистых функциях: ни `document`, ни `window`, ничего, связанного
с DOM.

## Smoke-тест

Отдельная, вторая проверка: `tests/smoke/dom-smoke.js`. Он реально прогоняет
последовательность `<script>` из `index.html` — настоящий бутстрап, настоящие
`sample-data/` — внутри минимальной самодельной DOM-заглушки (без `jsdom`,
без npm-зависимостей; ровно столько `document`/`window`/`sessionStorage`/
`requestAnimationFrame`, сколько нужно для одного прохода от загрузки до
экрана «Таблица»).

Он ловит то, что юнит-тесты структурно не видят: забытые экспорты,
неправильный порядок `<script>` в `index.html`, сломанную ленивую
межмодульную ссылку. Запуск:

```bash
node tests/smoke/dom-smoke.js                   # обычная загрузка -> Table
node tests/smoke/dom-smoke.js --simulate-crash   # восстановление после сторожевого таймера краша
```

Этот вид тестов не подхватывается `node --test`/`run_tests.sh` — имя файла
не совпадает с их шаблоном автообнаружения, поэтому запускать его нужно
отдельно.

{{% tip %}}
**Это не замена настоящему браузеру.** Если изменение затрагивает DOM API,
которого нет в заглушке — настоящий `querySelector`, CSSOM,
`getBoundingClientRect`, реальный клик, — smoke-тест такой баг не поймает.
Здесь всё ещё нужна ручная проверка в браузере глазами.
{{% /tip %}}

Сейчас этот вид теста покрывает один сквозной сценарий на экран; расширение
на больше тест-кейсов — в планах.

## Перед открытием PR

1. Запустить `./run_tests.sh` — все тесты зелёные — минимальная планка.
2. Запустить smoke-тест в обоих режимах (`node tests/smoke/dom-smoke.js`).
3. Для всего, что касается DOM/UI и не проверяется smoke-тестами — открыть
   `index.html` в браузере и проверить руками и глазами.
4. Написать тесты на то, что изменилось. Фикс без регрессионного теста или
   новый кусок логики без покрытия — это незаконченная работа:
   `preset.test.js` и `entities.test.js` — хороший пример того, как выглядит
   полноценное покрытие для кейсов редьюсера и граничных случаев
   парсинга/типизации соответственно.

## Тесты и релизы

Полный набор — и юнит-тесты, и smoke-тест в обоих режимах — прогоняется
перед релизом и должен пройти успешно, прежде чем изменение попадёт в
релиз, — см. [Релизы](../releases/).
